# 新增设备接口：
地址：/api/iot/devices/add
请求方式：Post
描述：新增设备
请求参数：
字段：deviceImei  类型：String  必填：true   描述：设备imei
字段：deviceModelId  类型：Long  必填：true   描述：设备型号id
字段：deviceModelName  类型：String  必填：true   描述：设备型号名称
字段：roomName  类型：String  必填：true   描述：安装点名称
字段：deviceType  类型：String  必填：true   描述：设备类型名称
字段：userId  类型：Long  必填：true   描述：用户id
请求参数说明：
{
	"deviceImei":"869975030003275",
	"deviceModelId":33,
	"deviceModelName":"SM-C03",
	"roomName":"居然创客大厦",
	"deviceType":"智能手环",
	"userId":1
}
返回结果：
{
	"code": "OK",
	"success": true,
	"message": {"data":"设备：869975030003275；添加成功！","deviceId":1213121}
}
接口逻辑：
1.根据传入的deviceImei，调用平台的"查询-获取单个设备信息接口"，如果未查到对应的设备信息，直接返回设备添加失败；如果返回成功，将前端提交的设备型号、设备类型、安装点以及平台返回的设备信息存入数据库设备表iot_devices，并将平台返回的接警人信息存入iot_device_contacts。
2. 同步将userId、deviceId、deviceImei、状态存入数据库用户设备关系表iot_user_devices。保存前先按user_id、device_id、device_imei查重；已存在且status不是1时更新为1；不存在时再插入。
3. 返回成功消息。
4. 失败时，返回失败消息。

# 历史逻辑修改
## 事件上报信息落库逻辑优化
1. 事件上报信息落库时，也会同步写设备表iot_devices和设备接警人表iot_device_contacts，为避免重复写，如果存在就不要写入，如果有变更就更新。
2. 不在设备表iot_devices中的设备，事件上报的信息，直接忽略，不用向iot_device_events (设备事件表)和iot_device_items (设备数据表)写入。

# 平台接口详情如下：
## 1.查询-获取单个设备信息接口
请求说明
描述：获取单个设备信息
请求方式：Post 
请求 URL： https://webapi.nbiotyun.com/api/v1/dev/get
请求参数
字段 字段类型 必填 说明
deviceId Long true 设备唯一 ID
deviceImei String true 设备 imei
fullFlag int true 全量查询标识 0：表示查询本级 1：表示查询所有 默认为 0
备注：deviceId 和 deviceImei 只需要传一个
请求参数示例：
{
  "deviceImei": "867561087297571",
  "fullFlag": 0
}

返回参数说明
  字段   字段类型   说明

  deviceImei String 设备 imei

  deviceModelName String 设备型号名称
  registerSign Int 入网注册标志 0 未注册 1 注册
  state Int 设备状态 0:正常 1:故障 2:报警 3:手动报警 4:离线 5:
  待删除 6:停用 7:未激活

  buildingName String 建筑物名称
  roomName String 安装点名称
  region Stirng 归属地区
  createTime String 创建时间
