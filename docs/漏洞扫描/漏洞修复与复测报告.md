## 3. 修复明细

### VULN-001 未登录可调用 AI 聊天/上传类接口

- 修复文件：
  - `backend/main.py`
- 修复内容：
  - 给 `POST /api/chat`、`POST /api/chat/polish`、`POST /api/chat/uploads`、`POST /api/upload` 增加 `Depends(get_current_user)`，未登录请求必须先通过认证。
  - 上传附件增加单次文件数量限制，当前最大 5 个文件。
  - 上传附件增加单文件 10MB 限制。
  - 上传附件增加 PDF、PNG、JPEG、WEBP 文件头校验，避免只信任客户端传入的 `content_type`。

### VULN-002 IoT 查询/管理接口缺少用户鉴权

- 修复文件：
  - `backend/iot_subscription/auth.py`
  - `backend/iot_subscription/device_api.py`
  - `backend/iot_subscription/alarm_api.py`
  - `backend/iot_subscription/event_api.py`
- 修复内容：
  - 新增 IoT 权限校验工具，统一从当前登录用户取 `current_user.id`。
  - IoT 设备新增、设备类型字典、设备参数查询/设置、指标趋势、检测报告、告警查询、设备详情、事件列表、事件详情均接入 `Depends(get_current_user)`。
  - 原请求体中的 `userId` 改为兼容字段，后端不再信任客户端传入的 `userId` 决定数据归属。
  - 查询或操作 IMEI、事件 ID 前校验 `iot_user_devices.user_id == current_user.id` 且绑定状态有效。
  - 无权限访问设备或事件时返回 403。

### VULN-003 IoT 平台密钥与订阅 Token 硬编码

- 修复文件：
  - `backend/iot_subscription/device_api.py`
  - `backend/iot_subscription/router.py`
- 修复内容：
  - 移除代码中的 IoT AppKey、AppSecret 默认值，改为从环境变量读取。
  - 生产环境缺少 `IOT_APP_KEY` 或 `IOT_APP_SECRET` 时启动失败。
  - 订阅 Token 改为从 `IOT_SUBSCRIBE_TOKEN` 读取，生产环境缺失时启动失败。
  - IoT 推送 `POST /api/iot/subscribe` 增加签名、时间戳窗口和 nonce 去重校验。
  - 签名比较改为 `hmac.compare_digest`，减少时序比较风险。
  - 日志中不再打印完整 IoT 请求签名和敏感头部。

### VULN-004 短信调试固定验证码生产误开风险

- 修复文件：
  - `backend/routers/auth.py`
- 修复内容：
  - 当 `APP_ENV` 或 `ENVIRONMENT` 为 `prod`/`production` 且 `SMS_DEBUG_MODE=true` 时，服务启动直接失败。
  - 保留本地调试能力，但阻断生产环境误开固定验证码。

### VULN-005 Redis 异常时安全能力降级

- 修复文件：
  - `backend/database.py`
  - `backend/middleware/__init__.py`
- 修复内容：
  - 生产环境缺少 `REDIS_URL` 时启动失败。
  - 生产环境 Redis 连接失败时不再静默回退到 `fakeredis`。
  - Redis 限流异常时，认证、短信、AI、上传、后台和 IoT 等高风险接口改为 fail-closed，返回 503。
  - 非敏感接口仍可在 Redis 短时异常时继续放行，避免全站不可用。

### VULN-006 App Token 本地存储与 WebView 注入风险

- 修复文件：
  - `flutter_app/pubspec.yaml`
  - `flutter_app/pubspec.lock`
  - `flutter_app/lib/services/app_storage_service.dart`
  - `flutter_app/lib/webview_page.dart`
  - `flutter_app/linux/flutter/generated_plugin_registrant.cc`
  - `flutter_app/linux/flutter/generated_plugins.cmake`
  - `flutter_app/macos/Flutter/GeneratedPluginRegistrant.swift`
  - `flutter_app/windows/flutter/generated_plugin_registrant.cc`
  - `flutter_app/windows/flutter/generated_plugins.cmake`
- 修复内容：
  - 新增 `flutter_secure_storage`。
  - 认证 Token 改为优先写入系统安全存储，Android 使用 encrypted shared preferences，iOS 使用 Keychain。
  - 读取 Token 时自动迁移旧版 SharedPreferences 中的遗留 Token，并删除旧键。
  - WebView 默认生产地址改为 HTTPS 域名。
  - WebView 增加可信域名白名单，生产只允许 HTTPS 可信域名；调试模式保留 localhost、127.0.0.1、10.0.2.2。
  - 注入 JS 前使用 `jsonEncode` 编码 Token 和 profileId，避免字符串拼接污染 JavaScript 上下文。

## 5. 复测结论

本次在 `feature/bug` 分支完成了原漏洞扫描报告中 6 项问题的代码层修复。后端 Python 编译通过，APP 相关 Dart 静态分析通过，关键鉴权点和敏感配置项静态复测通过。

## 6. 上线前要求

- 生产环境必须配置 `APP_ENV=production` 或 `ENVIRONMENT=production`。
- 生产环境必须配置 `REDIS_URL`，并确保 Redis 健康检查纳入发布门禁。
- 生产环境必须配置 `IOT_APP_KEY`、`IOT_APP_SECRET`、`IOT_SUBSCRIBE_TOKEN`。
- 生产环境必须保持 `SMS_DEBUG_MODE=false`。
- 已经在代码中出现过的 IoT AppKey、AppSecret、订阅 Token 应立即在第三方平台轮换。
- 部署后应使用未登录请求复测 `/api/chat`、`/api/chat/polish`、`/api/chat/uploads`、`/api/upload` 是否返回 401。
- 部署后应使用用户 A Token 请求用户 B 的设备 IMEI 或事件 ID，确认返回 403 或 404 且不返回数据。
- 部署后应使用无效签名、过期时间戳、重复 nonce 复测 `/api/iot/subscribe` 是否返回 403。
