# APP 与 API 接口漏洞扫描报告

## 1. 基本信息

- 项目名称：hospital-v5 / 时刻智护
- 测试日期：2026-09-03
- 测试对象：
  - Flutter App 代码：`flutter_app`
  - FastAPI 后端代码：`backend`
  - 线上 API：`https://web.sstkjgf.com`
- 测试方式：
  - 本地源码人工审计
  - 路由与鉴权边界检查
  - 敏感信息与调试开关检索
  - 线上低风险 API 验证
- 测试限制：
  - 未执行破坏性测试
  - 未执行高并发压测
  - 未执行真实设备参数下发
  - 未执行暴力破解、批量枚举真实用户或真实设备数据

## 2. 结论摘要

本次检查发现高风险问题 4 项，中风险问题 2 项。线上已低风险复现的主要问题是：未登录用户可以直接调用 `/api/chat` 并触发 AI 流式回答，存在资源滥用、费用消耗和服务可用性风险。

IoT 相关接口在本地源码中存在未鉴权、信任客户端传入 `userId`、硬编码平台密钥等高风险问题；但本次线上验证 `/api/iot/...` 返回 404，说明当前生产入口未暴露或当前线上版本未加载该路由。该问题仍应在代码层修复，避免后续部署时直接暴露。

| 编号 | 风险等级 | 问题 | 状态 |
| --- | --- | --- | --- |

| VULN-005 | 中 | Redis 异常时限流与登出黑名单降级为弱保护 | 源码确认 |
| VULN-006 | 中 | App Token 使用 SharedPreferences 存储并注入 WebView | 源码确认 |

## 4. 详细发现

### VULN-001 未登录可调用 AI 聊天/上传类接口

- 风险等级：高
- 影响范围：
  - `POST /api/chat`
  - `POST /api/chat/polish`
  - `POST /api/chat/uploads`
  - `POST /api/upload`
- 证据：
  - `backend/main.py:353` 定义 `/api/chat`，未使用 `Depends(get_current_user)`。
  - `backend/main.py:498` 定义 `/api/chat/polish`，未强制登录。
  - `backend/main.py:523` 定义 `/api/chat/uploads`，未强制登录。
  - `backend/main.py:543` 定义 `/api/upload`，未强制登录。
  - `flutter_app/lib/services/api_service.dart:502` 上传附件时 `token` 是可选参数。
  - 线上验证：未携带 `Authorization` 请求 `POST https://web.sstkjgf.com/api/chat`，返回 `HTTP/1.1 200 OK`，`Content-Type: text/event-stream`，并产生 AI 回答内容。
- 复现步骤：
  ```powershell
  curl.exe -i -X POST https://web.sstkjgf.com/api/chat `
    -F "mode=normal" `
    -F "message=安全连通性测试"
  ```
- 安全影响：
  - 任意未登录用户可消耗 AI 调用额度和服务器资源。
  - 可被脚本化调用造成费用损失或拒绝服务。
  - 上传类接口可被匿名用户提交文件进入后端处理链路。
- 修复建议：
  - `/api/chat`、`/api/chat/polish`、`/api/chat/uploads`、`/api/upload` 默认全部接入 `Depends(get_current_user)`。
  - 如果业务需要匿名体验，单独开放受限匿名接口，增加验证码、设备指纹、IP 限额、每日匿名额度和内容长度限制。
  - 上传接口校验文件魔数、MIME、扩展名、文件数量和总大小，避免仅信任 `content_type`。
  - 对 AI 调用增加用户级、IP 级、设备级组合限流和费用告警。

### VULN-002 IoT 查询/管理接口源码缺少用户鉴权

- 风险等级：高
- 影响范围：
  - `backend/iot_subscription/device_api.py`
  - `backend/iot_subscription/alarm_api.py`
  - `backend/iot_subscription/event_api.py`
- 证据：
  - `backend/iot_subscription/device_api.py:1425` `/api/iot/devices/add` 未使用鉴权依赖。
  - `backend/iot_subscription/device_api.py:1648` `/api/iot/device/param/set` 未使用鉴权依赖，且会调用第三方平台创建参数设置任务。
  - `backend/iot_subscription/device_api.py:1753` `/api/iot/device/metric/trend` 未使用鉴权依赖，且请求模型包含 `userId`。
  - `backend/iot_subscription/device_api.py:1878` `/api/iot/device/report` 未使用鉴权依赖，且请求模型包含 `userId`。
  - `backend/iot_subscription/alarm_api.py:70` `/api/iot/devices/alarm` 未使用鉴权依赖。
  - `backend/iot_subscription/alarm_api.py:167` `/api/iot/device/get` 未使用鉴权依赖。
  - `backend/iot_subscription/event_api.py:81` `/api/iot/devices/events` 未使用鉴权依赖。
  - `backend/iot_subscription/event_api.py:186` `/api/iot/devices/event/infos` 未使用鉴权依赖。
  - 线上验证：`POST https://web.sstkjgf.com/api/iot/device/report` 当前返回 404，暂未确认生产暴露。
- 安全影响：
  - 如果该路由部署到线上，攻击者可伪造 `userId` 查询其他用户设备报告。
  - 可通过 IMEI 或事件 ID 查询设备、报警、事件详情，形成敏感健康/设备数据泄露。
  - 参数设置接口可能被未授权调用，造成设备配置被恶意修改。
- 修复建议：
  - 所有用户侧 IoT 接口接入 `Depends(get_current_user)`。
  - 后端从 Token 中取 `current_user.id`，禁止信任客户端传入 `userId`。
  - 所有设备操作必须校验 `iot_user_devices.user_id == current_user.id`。
  - `/device/param/set` 建议仅允许管理员或已授权设备所有者操作，并记录审计日志。
  - 对 IMEI、eventId 类接口增加所有权校验，避免通过编号枚举数据。

### VULN-003 IoT 平台密钥与订阅 Token 硬编码，推送验签不足

- 风险等级：高
- 影响范围：
  - `backend/iot_subscription/device_api.py`
  - `backend/iot_subscription/router.py`
- 证据：
  - `backend/iot_subscription/device_api.py:221-223` 存在 IoT 平台地址、AppKey、AppSecret 默认硬编码值。
  - `backend/iot_subscription/router.py:51` 存在硬编码订阅 Token。
  - `backend/iot_subscription/router.py:56` 使用 MD5 签名校验。
  - `backend/iot_subscription/router.py:103` `POST /api/iot/subscribe` 接收推送数据时未校验签名、时间戳或 nonce。
  - `backend/iot_subscription/device_api.py:374` 日志会打印对外平台请求 headers，包含 appKey 和 signature。
- 安全影响：
  - 代码泄露即可能导致 IoT 平台凭据泄露。
  - 硬编码订阅 Token 容易被复用，且无法做到环境隔离和快速轮换。
  - 推送接收接口如果暴露，可被伪造数据写入日志/后续入库链路。
  - 缺少时间戳窗口和 nonce 去重时，存在重放风险。
- 修复建议：
  - 移除代码中的默认 AppKey/AppSecret/Token，强制从环境变量读取，缺失则启动失败。
  - 立即轮换已经硬编码过的 IoT 平台凭据和订阅 Token。
  - `POST /api/iot/subscribe` 增加签名校验、时间戳有效期校验、nonce 去重。
  - 日志中不要打印完整 appKey、signature、业务请求体中的敏感字段。
  - 如平台支持，使用 HMAC-SHA256 替代 MD5。

### VULN-004 短信调试万能验证码存在生产误开风险

- 风险等级：高
- 影响范围：
  - `backend/routers/auth.py`
- 证据：
  - `backend/routers/auth.py:38` 通过 `SMS_DEBUG_MODE` 控制调试模式。
  - `backend/routers/auth.py:39` 固定调试验证码为 `123456`。
  - `backend/routers/auth.py:295` 登录时如果 `SMS_DEBUG_MODE` 为真且验证码等于固定值，则允许登录。
- 当前状态：
  - 生产短信修复时已要求 `SMS_DEBUG_MODE=false`，本次报告按“配置型高风险”记录。
- 安全影响：
  - 如果生产环境误开 `SMS_DEBUG_MODE=true`，攻击者只需知道手机号即可使用固定验证码登录对应账号。
  - 对医疗健康类应用属于账号接管高风险。
- 修复建议：
  - 在生产环境增加硬性保护：`ENVIRONMENT=production` 时若 `SMS_DEBUG_MODE=true` 直接启动失败。
  - 删除固定万能验证码，或仅允许本地开发环境通过白名单手机号使用。
  - 后端禁止在任何非本地环境返回真实验证码或 `debug_code`。
  - 配置变更纳入发布检查项。

### VULN-005 Redis 异常时限流与登出黑名单降级为弱保护

- 风险等级：中
- 影响范围：
  - `backend/database.py`
  - `backend/middleware/__init__.py`
- 证据：
  - `backend/database.py:200-209` Redis 连接失败时回退到 `fakeredis`。
  - `backend/middleware/__init__.py` 限流异常时直接放行请求。
  - 短信次数、密码错误锁定、Token 黑名单均依赖 Redis。
- 安全影响：
  - Redis 异常时，多实例部署下限流和黑名单不再可靠。
  - 登出后的 Token 黑名单可能在进程重启或多进程间失效。
  - 登录爆破、短信轰炸的防护强度下降。
- 修复建议：
  - 生产环境 Redis 异常时不应静默降级为 `fakeredis`。
  - 健康检查应在 Redis 不可用时返回非 ready，阻止服务继续承接流量。
  - 限流失败至少对高风险接口采用保守策略，例如认证和短信接口 fail-closed。
  - 增加 Redis 可用性告警。

### VULN-006 App Token 本地存储与 WebView 注入风险

- 风险等级：中
- 影响范围：
  - `flutter_app/lib/services/app_storage_service.dart`
  - `flutter_app/lib/webview_page.dart`
- 证据：
  - `flutter_app/lib/services/app_storage_service.dart:7` 使用 `shared_preferences`。
  - `flutter_app/lib/services/app_storage_service.dart:48` 认证 Token 写入 SharedPreferences。
  - `flutter_app/lib/webview_page.dart:51` WebView 开启 `JavaScriptMode.unrestricted`。
  - `flutter_app/lib/webview_page.dart:85` 将 Token 拼接到 JavaScript 字符串注入页面。
  - `flutter_app/lib/webview_page.dart:31-37` 默认 WebView 地址为本地开发地址，可通过编译参数覆盖。
- 安全影响：
  - SharedPreferences 不是专用安全存储，Root、调试备份或恶意环境下 Token 风险更高。
  - WebView 若加载地址被配置到非可信域，Token 可能被页面脚本读取。
  - 直接字符串拼接注入 JS，若参数未严格转义，存在脚本上下文污染风险。
- 修复建议：
  - 使用 `flutter_secure_storage` 或平台 Keychain/Keystore 保存 Token。
  - WebView 只允许加载可信 HTTPS 白名单域名。
  - Token 注入使用安全转义，如 `jsonEncode(token)`，避免手工拼接 JS 字符串。
  - 能不用 WebView 传 Token 的场景，优先改成 App 原生请求后把最小必要数据传给页面。

## 6. 已观察到的有效安全控制

- 个人资料、问诊记录、聊天会话接口均依赖 `get_current_user`，并按 `current_user.id` 过滤。
- 后台管理接口均依赖 `get_current_admin`。
- 密码登录有失败次数锁定。
- 短信发送有手机号格式校验、发送冷却、每日次数限制。
- 响应头包含 HSTS、X-Content-Type-Options、X-Frame-Options、CSP、Referrer-Policy 等基础安全头。
- `/openapi.json` 与 `/api/openapi.json` 未直接暴露 FastAPI OpenAPI JSON。

## 7. 修复优先级

1. P0：给 `/api/chat`、`/api/chat/polish`、`/api/chat/uploads`、`/api/upload` 加鉴权或匿名限额保护。
2. P0：修复 IoT 源码接口鉴权，禁止客户端传入 `userId` 决定数据归属。
3. P0：移除并轮换硬编码 IoT 平台凭据和订阅 Token。
4. P1：生产环境强制禁止 `SMS_DEBUG_MODE=true`。
5. P1：Redis 不可用时避免认证/短信/黑名单保护静默降级。
6. P2：App Token 改用安全存储，并收紧 WebView 域名白名单和 JS 注入方式。

## 8. 建议整改验收标准

- 未登录访问 `/api/chat` 返回 401，或匿名模式必须有验证码/额度且不会使用登录用户资源。
- 未登录访问所有 `/api/iot/device*`、`/api/iot/devices*` 查询/管理接口返回 401。
- 使用用户 A 的 Token 请求用户 B 的 `userId` 或设备 IMEI 返回 403/404，不返回数据。
- 生产环境缺少 IoT/SMS/数据库/Redis 必要配置时服务启动失败或 readiness 失败。
- 代码库中不再存在真实 AppSecret、AccessKey、订阅 Token 默认值。
- App 侧 Token 不再落入 SharedPreferences，WebView 只加载可信 HTTPS 域名。
