# 性能优化方案
## 设备基本信息更新优化
1. 设备基本信息（如设备状态、设备地址、接警人信息）在设备上报时，通过缓存判断是否有变化，如果有变化，则更新对应的iot_devices表和iot_device_contacts表，然后删除对应的设备缓存信息，重新写入一条缓存记录；如果没有变化，则跳过设备基本信息更新流程，继续后续事件和指标的数据处理。
2. 查询缓存中没有对应的设备基本信息时，通过数据库后去查询iot_devices表和iot_device_contacts表，如果有判断是否有变化，如果有变化则更新对应表，并写入缓存中，如果缓存和表中都没有说明该设备没有绑定用户或在当前系统中不存在，不用报错，不写文件，也不写数据库，继续处理下一条数据即可。
3. 缓存的key为设备imei，value为设备基本信息的json字符串。例如：
```
"869975030003275":{
  "state":"正常",
  "address":"居然创客大厦",
  "device_contacts":[
    {
      "name":"张三",
      "phone":"13800000000"
    }
  ]
}
```

## 统一的缓存管理策略
1. 创建统一的缓存写入、查询、删除方法，用于管理设备缓存。
2. 缓存过期时间为60分钟，超过60分钟未更新，则自动删除。
3. 缓存写入时，使用异步线程池，将写入操作放到异步线程中执行，避免阻塞主线程。
4. 缓存写入时，使用批量写入，一次写入多个缓存项，提高写入效率。
  
## 数据库写入性能优化
1. 建数据库连接池，用于管理数据库连接接，提高数据库连接效率。
2. 文件或队列消费按批处理，按 200 条一批，每次写入数据库，提高写入效率。
3. 批处理除了按条数分批外，增加按时间分批的选项，按20秒分批，每次写入20秒内的数据，提高写入效率。
4. 事件表和指标表批量insert，一次写入多条数据，提高写入效率。
5. checkpoint 按批更新。
6. 分批的条数和时间配置，写入统一的配置文件.env中。

## 事件表拆分优化
1. 事件表iot_device_events拆分成多个子表，每个子表负责存储不同类型的事件数据iot_health_events、iot_alarm_events、iot_heartbeat_events；原来的iot_device_events表继续保留，用于存储所有类型的事件数据。
2. 每个子表的字段结构相同，只是字段的值不同，用于区分不同的事件类型。
3. 事件分类规则：
   - 健康事件：eventName 为 `温度数据上报`、`健康数据上报`、`计步和睡眠翻滚数据上报`。
   - 报警事件：`deviceState = 2` 且 `dataType = 2`。
   - 心跳事件：除健康事件和报警事件外，其他数据都归入心跳事件。
   - 如果同一条数据同时满足健康事件和报警事件条件，则同时写入健康事件表和报警事件表。

## 属性表拆分优化
1. 属性表iot_event_items拆分成多个子表，每个子表负责存储不同类型的属性数据iot_health_items、iot_alarm_items、iot_heartbeat_items；原来的iot_event_items表继续保留，用于存储所有类型的属性数据。
2. 每个子表的字段结构相同(除了iot_health_event_items表的attr_value字段是数值型)，只是字段的值不同，用于区分不同的属性类型。

## 增加设备最新指标表
1. 新增设备最新指标表iot_device_latest_metrics，用于存储设备最新的指标数据。

# 优化注意事项
1. 本次新增的表和原表保持双写（旧表只做迁移期双写，验证通过后旧表降级为兼容/归档，不再作为主查询表）。
2. 双写期不立即切接口；对账通过后，指标详情和报告页灰度切到新表。
3. 事件统一用字段sign_time作为事件发生时间。

## 索引设计

### 基础信息表索引

`iot_devices`：

```sql
-- 已有：设备 IMEI 唯一索引，用于设备基础信息查询和缓存回源
CREATE UNIQUE INDEX IF NOT EXISTS iot_devices_imei_key
ON iot_devices (imei);
```

`iot_device_contacts`：

```sql
-- 已有/建议保留：同一设备同一手机号唯一，避免联系人重复
CREATE UNIQUE INDEX IF NOT EXISTS idx_imei_phone
ON iot_device_contacts (imei, phone);

-- 按设备查询联系人
CREATE INDEX IF NOT EXISTS idx_iot_device_contacts_imei
ON iot_device_contacts (imei);
```

### 事件表索引

健康事件表 `iot_health_events`：

```sql
-- 平台签名去重
CREATE UNIQUE INDEX IF NOT EXISTS uq_iot_health_events_signature
ON iot_health_events (signature);

-- 按设备查询事件时间线
CREATE INDEX IF NOT EXISTS idx_iot_health_events_imei_sign_time
ON iot_health_events (imei, sign_time DESC, id DESC);

-- 按时间范围批量归档、统计
CREATE INDEX IF NOT EXISTS idx_iot_health_events_sign_time
ON iot_health_events (sign_time DESC);
```

报警事件表 `iot_alarm_events`：

```sql
-- 平台签名去重
CREATE UNIQUE INDEX IF NOT EXISTS uq_iot_alarm_events_signature
ON iot_alarm_events (signature);

-- 按设备查询报警时间线
CREATE INDEX IF NOT EXISTS idx_iot_alarm_events_imei_sign_time
ON iot_alarm_events (imei, sign_time DESC, id DESC);

-- 按数据类型查询报警，例如 data_type = 2
CREATE INDEX IF NOT EXISTS idx_iot_alarm_events_data_type_time
ON iot_alarm_events (data_type, sign_time DESC);

-- 按设备状态筛选报警状态
CREATE INDEX IF NOT EXISTS idx_iot_alarm_events_device_state_time
ON iot_alarm_events (device_state, sign_time DESC);

-- 今日报警、报警统计常用组合
CREATE INDEX IF NOT EXISTS idx_iot_alarm_events_type_state_time
ON iot_alarm_events (data_type, device_state, sign_time DESC);

-- 按报警处理状态查询
CREATE INDEX IF NOT EXISTS idx_iot_alarm_events_handler_status_time
ON iot_alarm_events (handler_status, sign_time DESC);
```

心跳事件表 `iot_heartbeat_events`：

```sql
-- 平台签名去重；如果心跳没有稳定 signature，可不建唯一索引
CREATE UNIQUE INDEX IF NOT EXISTS uq_iot_heartbeat_events_signature
ON iot_heartbeat_events (signature);

-- 按设备查询最近心跳
CREATE INDEX IF NOT EXISTS idx_iot_heartbeat_events_imei_sign_time
ON iot_heartbeat_events (imei, sign_time DESC, id DESC);

-- 按时间清理、归档
CREATE INDEX IF NOT EXISTS idx_iot_heartbeat_events_sign_time
ON iot_heartbeat_events (sign_time DESC);
```

### 属性表索引

健康属性表 `iot_health_event_items`：

```sql
-- 指标详情核心索引：单设备、单指标、时间范围查询
CREATE INDEX IF NOT EXISTS idx_iot_health_items_imei_attr_sign_id
ON iot_health_event_items (imei, attr_name, sign_time DESC, id DESC);

-- 按事件查询属性列表
CREATE INDEX IF NOT EXISTS idx_iot_health_items_event_id
ON iot_health_event_items (event_id);

-- 跨设备按指标做统计时使用
CREATE INDEX IF NOT EXISTS idx_iot_health_items_attr_sign_time
ON iot_health_event_items (attr_name, sign_time DESC);
```

报警属性表 `iot_alarm_event_items`：

```sql
-- 按报警事件查询扩展属性
CREATE INDEX IF NOT EXISTS idx_iot_alarm_items_event_id
ON iot_alarm_event_items (event_id);

-- 按设备、属性、时间查询报警属性
CREATE INDEX IF NOT EXISTS idx_iot_alarm_items_imei_attr_sign_id
ON iot_alarm_event_items (imei, attr_name, sign_time DESC, id DESC);
```

心跳属性表 `iot_heartbeat_event_items`：

```sql
-- 按心跳事件查询扩展属性
CREATE INDEX IF NOT EXISTS idx_iot_heartbeat_items_event_id
ON iot_heartbeat_event_items (event_id);

-- 按设备、属性、时间查询心跳属性
CREATE INDEX IF NOT EXISTS idx_iot_heartbeat_items_imei_attr_sign_id
ON iot_heartbeat_event_items (imei, attr_name, sign_time DESC, id DESC);
```

### 最新指标表索引

`iot_device_latest_metrics` 用于保存设备最新指标，同一设备同一指标只保留一条记录。数据库增加 `(imei, attr_name)` 唯一索引，避免并发写入产生重复最新值。

```sql
-- 报告页按设备批量获取最新指标，同时保证同一设备同一指标唯一
CREATE UNIQUE INDEX IF NOT EXISTS uq_iot_latest_metrics_imei_attr
ON iot_device_latest_metrics (imei, attr_name);

-- 按指标类型查询最新数据
CREATE INDEX IF NOT EXISTS idx_iot_latest_metrics_attr_time
ON iot_device_latest_metrics (attr_name, sign_time DESC);
```

程序写入时需要保证同一设备同一指标只保留一条最新记录：

```text
写入前按 imei + attr_name 查询
如果不存在则 insert
如果存在且本次 sign_time 更新，则 update
如果本次 sign_time 更旧，则忽略
```
