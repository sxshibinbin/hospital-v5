# 安小记 IoT 健康监测系统数据库设计说明书

版本: V1.0  
编制日期: 2026-07-30  
数据库: PostgreSQL

## 1. 设计目标

数据库设计围绕 IoT 数据高频接收、异步批量入库和移动端快速查询展开，目标包括:

1. 支持设备、联系人、用户设备绑定等主数据管理。
2. 支持 IoT 平台原始事件分类存储，区分健康、报警、心跳事件。
3. 支持最新指标快速查询，避免列表页频繁扫描历史明细。
4. 支持指标趋势、报警记录等时间序列查询。
5. 支持文件处理偏移量记录，保障断点续处理。
6. 支持设备参数本地保存和后续查询。

| `iot_health_event_items` | 分类明细表 | 健康指标明细。 |

## 3. 实体关系

核心关系如下:

1. 一个用户可绑定多台设备，关系保存在 `iot_user_devices`。
2. 一台设备可有多个联系人，关系保存在 `iot_device_contacts`。
3. 一台设备可产生多条健康、报警、心跳事件。
4. 一条事件可包含多条属性明细。
5. 一台设备的每个指标在 `iot_device_latest_metrics` 中保留一条最新值。
6. 一台设备的每个参数字段在 `iot_device_params` 中保留最新配置值。
7. 每个上传日志文件在 `iot_file_offsets` 中保留当前处理偏移量。

### 4.1 `iot_devices`

设备基础信息表，保存 IoT 设备从平台查询和业务维护得到的主数据。

| `device_version` | String | 设备版本。 |
| `device_model_id` | String | 平台设备型号 ID。 |
| `device_state` | Integer | 设备状态，0 正常，1 故障，2 报警，4 离线，8 隐患。 |

| `latitude` | Float | 纬度。 |
| `site` | String | 安装地点。 |
| `room_name` | String | 房间名称。 |
| `company_name` | String | 所属公司。 |

| 类型 | 字段 | 说明 |

## 5. 事件表设计

### 5.1 事件分类规则

IoT 平台推送数据入库时按规则分类:

| 分类 | 判断规则 | 说明 |
| --- | --- | --- |
| 健康事件 | `eventName` 为体温、健康、计步睡眠翻滚等数据上报事件 | 用于健康监测和趋势查询。 |
| 报警事件 | `dataType = 2` 且 `deviceState = 2` | 用于报警记录查询和报警数量统计。 |
| 心跳事件 | 不满足健康或报警规则的普通事件 | 用于设备活跃状态和普通上报留痕。 |

同一条数据可同时写入健康事件表和报警事件表。

### 5.2 通用字段

分类事件主表通常包含以下字段:

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | Integer/BigInteger | 主键。 |
| `imei` | String | 设备 IMEI。 |
| `event_name` | String | 事件名称。 |
| `data_type` | Integer | 平台数据类型。 |
| `device_state` | Integer | 设备状态。 |
| `sign_time` | DateTime | 平台签名时间或事件时间。 |
| `signature` | String | 平台签名，用于幂等去重。 |
| `nonce` | String | 平台随机串。 |
| `raw_data` | JSON/JSONB | 原始数据。 |
| `handler_status` | Integer | 处理状态。 |
| `handle_time` | DateTime | 处理时间。 |
| `alarm_reason` | String | 报警原因。 |
| `remark` | String | 备注。 |
| `created_at` | DateTime | 创建时间。 |

### 5.3 `iot_health_events`

健康事件主表，保存手表和健康设备上报的健康类事件。

主要用途:

- 健康数据历史留存。
- 趋势查询的事件归属。
- 设备最新状态辅助判断。

建议索引:

| 索引 | 字段 | 说明 |
| --- | --- | --- |
| 普通索引 | `imei, sign_time` | 按设备和时间查询健康事件。 |
| 唯一索引 | `signature` | 有签名时避免重复入库。 |

### 5.4 `iot_health_event_items`

健康指标明细表。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BigInteger | 主键。 |
| `event_id` | BigInteger | 健康事件 ID。 |
| `imei` | String | 设备 IMEI。 |
| `attr_name` | String | 指标名称。 |
| `attr_value` | Float | 指标数值。 |
| `sign_time` | DateTime | 指标时间。 |
| `created_at` | DateTime | 创建时间。 |

约束与索引:

| 类型 | 字段 | 说明 |
| --- | --- | --- |
| 外键 | `event_id` | 关联 `iot_health_events.id`。 |
| 索引 | `imei, attr_name, sign_time, id` | 支持单设备单指标趋势查询。 |
| 索引 | `attr_name, sign_time` | 支持按指标和时间统计。 |

### 5.5 `iot_alarm_events`

报警事件主表。

主要用途:

- 报警记录列表。
- 健康监测列表中报警数量统计。
- 后续报警处理状态扩展。

建议索引:

| 索引 | 字段 | 说明 |
| --- | --- | --- |
| 普通索引 | `imei, sign_time` | 按设备和时间查询报警。 |

| 唯一索引 | `signature` | 有签名时避免重复入库。 |

| 类型 | 字段 | 说明 |

心跳事件主表，用于保存普通状态上报或未归类为健康、报警的数据。

建议索引:

| 索引 | 字段 | 说明 |
| --- | --- | --- |

### 5.8 `iot_heartbeat_event_items`

## 6. 最新指标表

### 6.1 `iot_device_latest_metrics`

设备最新指标表，用于健康监测列表和设备详情快速展示。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | Integer | 主键。 |
| `imei` | String | 设备 IMEI。 |
| `attr_name` | String | 指标名称。 |
| `attr_value` | Float | 最新指标值。 |
| `sign_time` | DateTime | 指标上报时间。 |
| `updated_at` | DateTime | 更新时间。 |

约束与索引:

| 类型 | 字段 | 说明 |
| --- | --- | --- |
| 唯一约束 | `imei, attr_name` | 一台设备一个指标只保留一条最新值。 |
| 索引 | `attr_name, sign_time` | 支持按指标和时间扩展统计。 |

更新规则:

1. 健康指标明细入库时同步更新。
2. 当新指标时间晚于现有指标时间时覆盖。
3. 列表页和详情页优先读取该表，不直接从历史表中取最新值。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | Integer | 主键。 |
| `imei` | String | 设备 IMEI。 |
| `param_code` | String/Integer | 平台参数或指令编码。 |
| `field_name` | String | 参数字段名。 |
| `param_value` | String | 参数值。 |
| `create_by` | Integer/String | 创建人或操作人。 |
| `created_at` | DateTime | 创建时间。 |
| `updated_at` | DateTime | 更新时间。 |

约束与索引:

| 类型 | 字段 | 说明 |
| --- | --- | --- |
| 外键 | `imei` | 关联 `iot_devices.imei`。 |
| 唯一约束 | `imei, param_code, field_name` | 同一设备同一参数字段只保留一条配置。 |

写入规则:

1. 参数设置接口先调用 IoT 平台创建任务。
2. 平台全部返回成功后，本地执行新增或更新。
3. 平台失败时，不更新本地参数值。

## 8. 文件处理控制表

### 8.1 `iot_file_offsets`

上传日志处理偏移量表，用于文件监控服务断点续处理。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `file_path` | String | 文件路径，主键。 |
| `offset_bytes` | BigInteger | 已处理字节偏移。 |
| `file_size` | BigInteger | 最近记录的文件大小。 |
| `status` | String | 处理状态。 |
| `updated_at` | DateTime | 更新时间。 |
| `completed_at` | DateTime | 完成时间。 |

约束与索引:

| 类型 | 字段 | 说明 |
| --- | --- | --- |
| 主键 | `file_path` | 一个文件一条处理进度。 |
| 索引 | `status, updated_at` | 查询待处理、处理中、异常文件。 |

处理规则:

1. 文件监控服务只处理达到成熟时间的文件。
2. 每批处理后更新 `offset_bytes`。
3. 文件处理完成后更新状态和完成时间。
4. 服务重启后从记录偏移量继续读取。

## 10. 查询设计

### 10.1 健康监测列表

数据来源:

1. `iot_user_devices`: 查询当前用户绑定设备。
2. `iot_devices`: 查询设备基础信息和状态。
3. `iot_device_latest_metrics`: 查询每台设备最新健康指标。
4. `iot_alarm_events`: 统计雷达或设备报警数量。
5. 分类事件表: 查询设备最新上报时间。

设计原则:

- 列表页避免扫描历史明细取最新指标。
- 多设备查询应批量读取，减少逐台设备循环查询。
- 未绑定设备不应出现在用户列表中。

### 10.2 设备详情

数据来源:

1. `iot_devices`: 设备基础信息。
2. `iot_user_devices`: 校验用户绑定关系。
3. `iot_device_latest_metrics`: 最新指标。
4. 分类事件表: 最新上报时间和设备状态。

### 10.3 指标趋势

数据来源:

1. `iot_user_devices`: 校验用户设备绑定关系。
2. `iot_health_event_items`: 查询指定指标和时间范围内的数据点。

关键索引:

```text
(imei, attr_name, sign_time, id)
```

### 10.4 报警记录

数据来源:

1. `iot_user_devices`: 校验用户设备绑定关系。
2. `iot_alarm_events`: 查询报警主记录。
3. `iot_alarm_event_items`: 查询报警属性明细。

常用查询条件:

- `imei`
- `handler_status`
- `sign_time`

如报警查询量持续增长，可增强索引:

```text
(imei, handler_status, sign_time DESC, id DESC)
```

## 11. 索引设计原则

1. 设备维度时间序列查询使用 `(imei, sign_time)` 或 `(imei, attr_name, sign_time, id)`。
2. 最新值查询通过 `iot_device_latest_metrics` 的唯一键完成。
3. 报警状态筛选使用设备、处理状态、时间组合索引。
4. 文件处理控制通过状态和更新时间索引定位异常或待处理文件。
5. 幂等写入优先使用平台签名字段的唯一索引；签名为空时需结合业务字段控制重复风险。

## 12. 数据一致性设计

| 场景 | 设计 |
| --- | --- |
| 平台重复推送 | 使用签名唯一索引或业务去重逻辑避免重复事件。 |
| 接收接口高并发 | 接口只负责校验和落盘，入库异步执行。 |
| 文件处理失败 | 偏移量记录最后成功位置，下次从该位置继续。 |
| 最新指标更新 | 仅使用更晚 `sign_time` 的指标覆盖旧值。 |
| 参数下发失败 | 不更新本地参数表，避免本地状态与设备不一致。 |

## 13. 数据保留与扩展建议

1. 历史事件数据量持续增长后，应按月份或日期对分类事件表和明细表进行分区。
2. 年趋势、跨设备统计等查询应建设汇总表，避免直接扫描全量明细。
3. 多实例部署时，应评估本地文件落盘方案，必要时改为共享队列或消息中间件。
4. 报警处理流程扩展时，可增加处理人、处理结果、处理附件、工单 ID 等字段。
5. 设备类型和参数映射若频繁变化，可从代码常量迁移为数据库配置表。

## 14. 初始化与迁移注意事项

1. 初始化主数据表后，应先维护 `iot_device_types`。
2. 添加设备时，应保证 `iot_devices` 与 `iot_user_devices` 同步写入。
3. 历史通用事件表迁移到分类事件表时，应明确迁移范围和去重规则。
4. 新增索引应避开业务高峰期，历史大表建议使用在线建索引方式。
5. 调整字段类型前，应评估移动端接口响应和历史数据兼容性。
