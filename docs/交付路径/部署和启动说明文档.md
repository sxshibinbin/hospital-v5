# 安小记 IoT 健康监测系统部署和启动说明文档

版本: V1.0  
编制日期: 2026-07-30  
适用范围: 后端服务、前端站点、管理端站点、移动端 APK、IoT 平台订阅接入

## 1. 部署组成

系统由以下部分组成:

| 模块 | 路径 | 说明 |
| --- | --- | --- |
| 后端服务 | `backend` | FastAPI 服务，提供认证、业务接口、IoT 订阅接收、文件监控和批量入库能力。 |
| 用户前端 | `frontend` | Vite + React 前端站点。 |
| 管理端 | `admin_web` | Vite + React 管理端站点。 |
| 移动端 | `flutter_app` | Flutter Android 应用，打包输出 APK。 |
| 压测程序 | `压测` | IoT 数据接收和处理性能压测程序。 |
| 交付文档 | `docs\交付路径` | 需求、操作、数据库、部署启动等交付文档。 |

## 2. 环境要求

### 2.1 后端运行环境

| 组件 | 建议版本 | 说明 |
| --- | --- | --- |
| Python | 3.11 | 后端 Dockerfile 使用 `python:3.11-slim`。 |
| PostgreSQL | 15 | Docker 部署使用 `postgres:15-alpine`。 |
| Redis | 7 | Docker 部署使用 `redis:7-alpine`。 |
| Docker | 20+ | 容器化部署使用。 |
| Docker Compose | V2 | 推荐使用 `docker compose` 命令。 |

### 2.2 前端和移动端环境

| 组件 | 说明 |
| --- | --- |
| Node.js | 用于构建 `frontend` 和 `admin_web`。 |
| npm | `frontend` 目录已有 `package-lock.json`，建议使用 npm。 |
| pnpm | `admin_web` 目录已有 `pnpm-lock.yaml`，建议使用 pnpm。 |
| Flutter SDK | APK 打包脚本默认使用 `D:\flutter`。 |
| JDK | APK 打包脚本默认使用 `C:\Program Files\Java\jdk-17.0.12`。 |
| Android SDK | APK 打包脚本默认使用 `flutter_app\.android-sdk`。 |

## 3. 端口规划

| 服务 | 默认端口 | 说明 |
| --- | ---: | --- |
| 后端 API | 8000 | FastAPI 服务端口。 |
| 用户前端 | 5174 | 根目录 Nginx Compose 映射端口。 |
| 管理端 | 5173 | 根目录 Nginx Compose 映射端口。 |
| PostgreSQL | 5432 | 数据库端口，生产环境可不暴露到宿主机。 |
| Redis | 6379 | 缓存端口，生产环境可不暴露到宿主机。 |

生产环境建议通过 Nginx、网关或负载均衡器暴露 HTTPS 域名，数据库和 Redis 端口仅在内网访问。

## 4. 后端配置

### 4.1 配置文件

后端配置文件位于:

```text
backend\.env
```

可基于示例文件创建:

```powershell
cd backend
copy .env.example .env
```

Linux 服务器可使用:

```bash
cd backend
cp .env.example .env
```

### 4.2 必填配置

| 配置项 | 说明 |
| --- | --- |
| `SECRET_KEY` | JWT 签名密钥。 |
| `ENCRYPTION_KEY` | AES/Fernet 加密密钥，用于敏感数据加密。 |
| `DATABASE_URL` | 主业务数据库连接地址，SQLAlchemy 异步驱动格式。 |
| `IOT_DATABASE_URL` | IoT 模块数据库连接地址，psycopg 同步驱动格式。 |
| `POSTGRES_PASSWORD` | Docker PostgreSQL 初始化密码。 |
| `REDIS_URL` | Redis 连接地址。 |

本地 PostgreSQL 示例:

```text
DATABASE_URL=postgresql+asyncpg://postgres:CHANGE_ME@localhost:5432/hospital
IOT_DATABASE_URL=postgresql://postgres:CHANGE_ME@localhost:5432/hospital
REDIS_URL=redis://localhost:6379/0
```

Docker Compose 内部网络示例:

```text
DATABASE_URL=postgresql+asyncpg://postgres:CHANGE_ME@postgres:5432/hospital
IOT_DATABASE_URL=postgresql://postgres:CHANGE_ME@postgres:5432/hospital
REDIS_URL=redis://redis:6379/0
```

### 4.3 可选配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `APP_PORT` | 8000 | Docker Compose 暴露的后端端口。 |
| `LOG_LEVEL` | `INFO` | 日志级别。 |
| `LOG_FORMAT` | `json` | 日志格式。 |
| `SQL_ECHO` | `false` | 是否输出 SQL 日志。 |
| `CORS_ALLOWED_ORIGINS` | 开发端口白名单 | 生产环境应配置前端实际域名，多个域名用英文逗号分隔。 |
| `DASHSCOPE_API_KEY` | 空 | AI 咨询能力需要配置。 |
| `ALIBABA_CLOUD_ACCESS_KEY_ID` | 空 | 运营商一键登录需要配置。 |
| `ALIBABA_CLOUD_ACCESS_KEY_SECRET` | 空 | 运营商一键登录需要配置。 |
| `ALIBABA_CLOUD_DYPNAS_REGION_ID` | `cn-hangzhou` | 阿里云号码认证区域。 |

### 4.4 IoT 处理配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `IOT_DB_POOL_MIN_SIZE` | 1 | IoT 数据库连接池最小连接数。 |
| `IOT_DB_POOL_MAX_SIZE` | 10 | IoT 数据库连接池最大连接数。 |
| `IOT_FILE_BATCH_SIZE` | 200 | 文件监听单批最大处理记录数。 |
| `IOT_FILE_BATCH_SECONDS` | 20 | 单轮文件处理最长耗时。 |
| `IOT_DEVICE_CACHE_TTL_SECONDS` | 3600 | 已绑定设备缓存时间。 |
| `IOT_DEVICE_NEGATIVE_CACHE_TTL_SECONDS` | 300 | 未绑定设备负缓存时间。 |
| `IOT_BOUND_FILTER_ENABLED` | `true` | 是否只接收已绑定设备数据。 |

IoT 平台订阅校验 token 当前在 `backend\iot_subscription\router.py` 中配置为 `IOT_SUBSCRIBE_TOKEN`，部署时应确保该值与 IoT 平台订阅配置一致。生产环境建议后续改为环境变量管理。

## 5. 数据库初始化

后端启动生命周期中会执行:

1. 主业务 SQLAlchemy 模型建表。
2. 默认系统数据初始化。
3. Redis 连接检查。
4. IoT 数据库连接池初始化。
5. IoT 文件偏移表、设备参数表、性能优化表和相关索引检查。
6. IoT 上传日志文件监听任务启动。

首次部署建议启动后检查健康接口和数据库表是否创建成功。

健康检查:

```text
GET /api/health
GET /api/health/ready
```

如需要从旧 SQLite 数据迁移到 PostgreSQL，可参考后端脚本:

```powershell
cd backend
python scripts\export_sqlite.py
python scripts\import_to_pg.py
```

迁移前应先确认 `DATABASE_URL` 已指向目标 PostgreSQL，并做好数据库备份。

## 6. Windows 本地启动

### 6.1 安装后端依赖

```powershell
cd D:\WorkSpace\WorkSpace_\hospital-v5\backend
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -U pip
pip install -r requirements.txt
```

如果本机已有合适的 Python 虚拟环境，可直接激活后安装依赖。

### 6.2 启动数据库和 Redis

本地开发可以使用本机 PostgreSQL/Redis，也可以使用 Docker 启动依赖服务。若使用 `backend\docker-compose.yml`，会同时启动后端、PostgreSQL、Redis；若只想单独使用依赖服务，可根据本机环境自行启动 PostgreSQL 和 Redis。

启动前确认 `backend\.env` 中:

```text
DATABASE_URL
IOT_DATABASE_URL
REDIS_URL
SECRET_KEY
ENCRYPTION_KEY
```

均已设置。

### 6.3 启动后端

推荐使用后端目录下的启动脚本:

```powershell
cd D:\WorkSpace\WorkSpace_\hospital-v5\backend
.\start.bat
```

脚本行为:

- 默认端口为 8000。
- 启动前会停止旧的同端口 `uvicorn main:app` 进程。
- 日志写入 `backend\logs\server-8000-时间戳.log`。
- 当前日志指针写入 `backend\.server.log`。
- 服务 PID 写入 `backend\.server.pid`。

常用命令:

```powershell
.\start.bat
.\start.bat restart
.\start.bat status
.\start.bat stop
```

也可以直接启动:

```powershell
cd D:\WorkSpace\WorkSpace_\hospital-v5\backend
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

### 6.4 验证后端

浏览器或接口工具访问:

```text
http://localhost:8000/docs
http://localhost:8000/api/health
http://localhost:8000/api/health/ready
```

`/api/health/ready` 返回 `ready` 时，表示数据库和 Redis 检查通过。

## 8. Docker 部署后端

### 8.1 准备配置

```bash
cd backend
cp .env.example .env
```

编辑 `.env`，至少确认:

```text
SECRET_KEY=
ENCRYPTION_KEY=
POSTGRES_PASSWORD=
POSTGRES_DB=hospital
POSTGRES_USER=postgres

CORS_ALLOWED_ORIGINS=https://your-frontend-domain.com
```

Docker Compose 会覆盖容器内连接地址:

```text
DATABASE_URL=postgresql+asyncpg://postgres:<password>@postgres:5432/hospital
IOT_DATABASE_URL=postgresql://postgres:<password>@postgres:5432/hospital
REDIS_URL=redis://redis:6379/0
```

### 8.2 启动

```bash
cd backend
docker compose up -d --build
```

### 8.3 查看状态

```bash
docker compose ps
docker compose logs -f app
```

健康检查:

```bash
curl http://localhost:8000/api/health
curl http://localhost:8000/api/health/ready
```

### 8.4 停止和重启

```bash
cd backend
docker compose restart app
docker compose down
```

注意: `docker compose down` 不会删除命名卷；如执行带 `-v` 的命令会删除 PostgreSQL/Redis 数据卷，生产环境禁止随意使用。

## 9. Docker 部署前端和管理端

根目录 `docker-compose.yml` 使用 Nginx 托管两个静态站点:

| 站点 | 容器内目录 | 宿主机端口 |
| --- | --- | ---: |
| 用户前端 | `/usr/share/nginx/html/frontend/dist` | 5174 |
| 管理端 | `/usr/share/nginx/html/admin_web/dist` | 5173 |

### 9.1 构建用户前端

```bash
cd frontend

npm run build
```

### 9.2 构建管理端

```bash
cd admin_web

```

### 9.3 配置 Nginx 代理

部署前应检查根目录:

```text
nginx.conf
```

其中 `/api/` 代理地址需要指向实际后端地址:

```nginx
location /api/ {
    proxy_pass http://<backend-host>:8000/api/;
}
```

当前配置中代理地址为固定 IP，正式部署时应替换为目标服务器内网地址、服务名或网关地址。

### 9.4 启动 Nginx

## 10. 移动端 APK 打包和启动

### 10.1 打包前检查

确认:

1. 后端服务已启动。
2. 手机和后端电脑在同一网络，或手机能访问后端公网地址。
3. 不要给移动端配置 `localhost` 或 `127.0.0.1`。
4. Flutter、JDK、Android SDK 路径与 `build-apk.bat` 中配置一致。

### 10.2 默认打包

在项目根目录执行:

```powershell
.\build-apk.bat
```

脚本会自动检测本机 IPv4，并按 `http://IP:8000` 写入移动端 API 地址。

### 10.3 指定后端地址

```powershell
.\build-apk.bat 172.19.51.96
.\build-apk.bat 172.19.51.96 8000
.\build-apk.bat http://172.19.51.96:8000
```

### 10.4 输出文件

APK 输出路径:

```text
dist\hospital-v5-harmonyos-4.2-debug.apk
```

安装后验证:

1. App 名称显示为安小记。
2. 可正常登录。
3. 健康监测页面能加载设备数据。
4. 设备详情、报警记录、参数设置页面接口访问正常。

## 11. IoT 平台订阅配置

### 11.1 订阅地址

在 IoT 平台配置后端订阅地址:

```text
http://<server-host>:8000/api/iot/subscribe
```

生产环境建议使用 HTTPS:

```text
https://<domain>/api/iot/subscribe
```

### 11.2 URL 校验

平台会通过 GET 请求进行 URL 校验:

```text
GET /api/iot/subscribe
```

后端使用 token、timestamp、nonce 计算签名并与平台传入 signature 比对。

### 11.3 数据推送

平台推送设备数据:

```text
POST /api/iot/subscribe
```

后端处理结果:

| 场景 | 行为 |
| --- | --- |
| 设备已绑定 | 写入上传日志文件，后续异步入库。 |
| 设备未绑定 | 返回 `success`，不写上传日志、不入业务库。 |
| 请求体异常 | 记录异常日志，返回平台可识别结果。 |

上传日志目录:

```text
backend\logs\app_upload\YYYYMMDD\HH\upload_YYYYMMDD_HH_001.log
```

## 14. 日志和排查

### 14.1 后端日志

本地脚本启动日志:

```text
backend\logs\server-8000-*.log
backend\.server.log
```

Docker 日志:

```bash
cd backend
docker compose logs -f app
```

### 14.2 IoT 上传日志

```text
backend\logs\app_upload
```

应重点检查:

- 是否有新小时目录生成。
- 文件是否持续增长。
- 日志行是否为完整 JSON 推送记录。
- 是否存在大量未绑定设备被过滤。

### 14.3 文件处理偏移

数据库表:

```text
iot_file_offsets
```

排查方向:

- `offset_bytes` 是否持续增长。
- `status` 是否长期停留在异常或处理中状态。
- `updated_at` 是否长时间未更新。

## 15. 常见问题

| 问题 | 原因 | 处理方式 |
| --- | --- | --- |
| 后端启动即退出 | `.env` 缺少 `DATABASE_URL`、`SECRET_KEY` 或 `ENCRYPTION_KEY` | 补齐配置后重新启动。 |
| `/api/health/ready` 返回失败 | PostgreSQL 或 Redis 不可用 | 检查连接地址、端口、防火墙和容器状态。 |
| 手机无法访问后端 | APK 内后端地址为 `localhost` 或网络不通 | 重新使用局域网 IP 或公网 HTTPS 地址打包。 |
| IoT 平台 URL 校验失败 | token、timestamp、nonce、signature 不匹配 | 确认平台 token 与后端 `IOT_SUBSCRIBE_TOKEN` 一致。 |
| 有推送但页面无数据 | 设备未绑定、文件处理未运行或数据未归类为健康/报警 | 检查绑定关系、上传日志、文件偏移和事件表。 |
| 前端访问 API 失败 | Nginx `proxy_pass` 指向错误后端 | 修改 `nginx.conf` 并重启 Nginx 容器。 |
| 参数下发失败 | IoT 平台指令创建失败或参数不支持 | 查看后端日志和平台返回信息，确认设备类型和参数映射。 |
| 压测后积压不清空 | 数据库写入慢或批处理配置偏小 | 调整连接池、批处理参数，检查慢 SQL 和磁盘 IO。 |

## 16. 发布注意事项

1. 生产环境发布前必须备份 PostgreSQL 数据。
2. `.env` 不应提交到代码仓库，也不应放入公开交付包。
3. 生产环境应启用 HTTPS，IoT 平台订阅地址优先使用域名。
4. 数据库和 Redis 端口不建议暴露到公网。
5. 修改 `nginx.conf` 后需要重启 Nginx 容器。
6. 修改后端 `.env` 后需要重启后端服务。
7. APK 后端地址变更后必须重新打包并重新安装。
8. 执行压测前应确认目标环境，避免误压生产系统。
