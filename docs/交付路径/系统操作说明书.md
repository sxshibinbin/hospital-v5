# 安小记 IoT 健康监测系统操作说明书

版本: V1.0  
编制日期: 2026-07-30  
适用范围: 安小记移动端、后端 IoT 接口服务、数据处理服务、压测与打包流程

## 1. 系统概述

安小记 IoT 健康监测系统用于接入智能手表、睡眠雷达、跌倒雷达等设备数据。用户在移动端查看设备状态、健康指标、报警记录和趋势数据，并可维护部分设备参数。后端负责移动端接口、IoT 平台数据订阅接收、日志落盘、批量入库和查询聚合。

## 2. 使用前准备

### 2.1 服务准备

1. 后端服务已启动，移动端可访问后端 API 地址。
2. PostgreSQL 数据库已创建并完成表结构初始化。
3. IoT 平台账号、接口地址、签名密钥等配置已在后端环境中设置。
4. 文件处理服务已启动，并可访问上传日志目录。
5. 移动端安装包已使用正确后端地址打包。

### 2.2 移动端网络要求

手机真机调试时，后端地址不能使用 `localhost` 或 `127.0.0.1`。应使用电脑在局域网中的 IP 地址，例如:

```text
http://172.19.51.96:8000
```

## 3. 登录与当前用户

### 3.1 登录方式

移动端支持以下登录方式:

| 登录方式 | 接口 |
| --- | --- |
| 密码登录 | `POST /api/auth/login` |
| 短信登录 | `POST /api/auth/login/sms` |
| 运营商一键登录 | `POST /api/auth/login/carrier` |

登录成功后，移动端保存后端返回的 token。

### 3.2 获取当前用户

移动端通过以下接口获取当前用户信息:

```text
GET /api/auth/me
Authorization: Bearer <token>
```

当前用户信息至少包含:

| 字段 | 说明 |
| --- | --- |
| `id` | 当前用户 ID |
| `phone` | 手机号 |
| `displayName` | 展示名称 |
| `defaultProfileName` | 默认档案名称 |
| `avatarKey` | 头像标识 |

健康监测、设备列表、设备详情、趋势、报警和参数操作均应基于当前登录用户执行。

## 4. 健康监测页面操作

### 4.1 进入页面

用户登录后进入健康监测页面，页面根据当前用户 ID 调用设备监测列表接口:

```text
POST /api/iot/device/report
```

### 4.2 查看设备列表

页面展示当前用户已绑定设备。每台设备应展示:

- 设备 IMEI。
- 设备类型和型号。
- 房间或安装位置。
- 最新上报时间。
- 当前设备状态。
- 智能手表类设备的最新健康指标。
- 雷达类设备的报警数量或状态信息。

### 4.3 空数据处理

当当前用户未绑定设备或设备暂无上报数据时，页面应显示空状态，不应展示固定用户或演示数据。

## 5. 新增设备操作

### 5.1 获取设备类型

新增设备前，移动端调用:

```text
GET /api/iot/device/type_dict
```

页面将设备类型作为下拉选项展示。

### 5.2 提交设备信息

用户填写或选择以下信息:

| 信息 | 说明 |
| --- | --- |
| 设备 IMEI | 必填，设备唯一标识。 |
| 设备类型 | 必填，例如 GK8、GS17、SM-C03、RT-C03AI。 |
| 房间/位置 | 建议填写，用于列表和详情展示。 |
| 联系人信息 | 如业务需要，可填写联系人姓名和电话。 |

提交后调用:

```text
POST /api/iot/devices/add
```

后端会先向 IoT 平台查询设备基础信息。查询成功后，保存设备信息、联系人信息和用户设备绑定关系。

### 5.3 常见结果

| 场景 | 页面处理 |
| --- | --- |
| 新增成功 | 提示成功并刷新设备列表。 |
| 设备已存在且已绑定 | 提示重复绑定或已添加。 |
| IoT 平台未查询到设备 | 提示设备不存在或平台不可用。 |
| 参数不完整 | 提示用户补充必填项。 |

## 6. 设备详情与趋势操作

### 6.1 查看设备详情

用户在健康监测列表中点击设备，移动端调用:

```text
POST /api/iot/device/get
```

详情页展示设备基础信息、状态、最新上报时间和指标摘要。

### 6.2 查询指标趋势

趋势图调用:

```text
POST /api/iot/device/metric/trend
```

请求参数包括:

| 参数 | 说明 |
| --- | --- |
| `userId` | 当前登录用户 ID。 |
| `deviceImei` | 设备 IMEI。 |
| `itemType` | 指标类型。 |
| `queryType` | 查询粒度。 |
| `startDate` | 开始时间。 |
| `endDate` | 结束时间。 |

指标类型:

| `itemType` | 指标 |
| ---: | --- |
| 0 | 心率 |
| 1 | 血氧 |
| 2 | 血压 |
| 3 | 体温 |
| 4 | 步数 |

查询粒度:

| `queryType` | 粒度 |
| ---: | --- |
| 0 | 日 |
| 1 | 周 |
| 2 | 月 |
| 3 | 年 |

周查询最长不应超过 7 天。若设备不属于当前用户，后端应拒绝查询。

## 7. 报警记录操作

### 7.1 进入报警记录

用户可从设备详情或报警入口进入报警记录页面。页面调用:

```text
POST /api/iot/devices/alarm
```

### 7.2 筛选条件

支持以下筛选:

| 条件 | 说明 |
| --- | --- |
| 设备 IMEI | 查询指定设备报警。 |
| 处理状态 | 全部、未处理、已处理。 |
| 开始时间 | 报警发生开始时间。 |
| 结束时间 | 报警发生结束时间。 |

未传时间范围时，后端默认查询当天报警记录。

### 7.3 列表展示

报警记录应展示:

- 设备信息。
- 报警时间。
- 报警原因或事件名称。
- 处理状态。
- 备注信息。

## 8. 设备参数维护操作

### 8.1 查询参数

用户进入参数设置页面后，移动端调用:

```text
POST /api/iot/device/param/get
```

页面根据设备类型展示对应参数。

### 8.2 设置参数

用户修改参数后调用:

```text
POST /api/iot/device/param/set
```

后端处理流程:

1. 校验设备是否存在。
2. 根据设备类型将页面参数转换为平台指令编码和字段名。
3. 调用 IoT 平台创建指令任务。
4. 所有指令下发成功后，保存本地参数值。
5. 任一指令失败时，返回失败信息，不更新本地参数值。

### 8.3 参数范围

| 设备类型 | 可维护参数 |
| --- | --- |
| GK8/GS17 | 心率采集间隔、体温采集间隔、计步开关、睡眠起止时间、跌倒报警开关、跌倒灵敏度等。 |
| SM-C03 | 检测模式、心率开关、呼吸开关、睡眠开关、长时间无人计时开关、无人持续时长、异常挣扎开关、存在检测开关等。 |
| RT-C03AI | 有人报警开关、无人报警开关、跌倒高度等。 |

## 9. IoT 平台订阅操作

### 9.1 URL 校验

在 IoT 平台配置订阅地址时，平台会请求:

```text
GET /api/iot/subscribe
```

后端按平台签名规则校验请求参数，校验通过后返回平台要求的验证结果。

### 9.2 数据推送

IoT 平台设备数据推送到:

```text
POST /api/iot/subscribe
```

后端处理规则:

1. 解析平台推送 JSON。
2. 判断设备是否已绑定。
3. 未绑定设备返回 `success`，但不写入业务数据。
4. 已绑定设备写入上传日志文件。
5. 接口快速返回，后续由文件处理服务异步入库。

## 10. 数据处理服务操作

### 10.1 处理机制

数据处理服务持续扫描上传日志目录，按成熟文件读取新增内容，并根据偏移量记录继续处理。默认处理参数包括:

| 配置 | 说明 |
| --- | --- |
| `IOT_FILE_BATCH_SIZE` | 单批处理记录数，默认 200。 |
| `IOT_FILE_BATCH_SECONDS` | 批处理时间窗口，默认 20 秒。 |
| `IOT_DB_POOL_MIN_SIZE` | 数据库连接池最小连接数，默认 1。 |
| `IOT_DB_POOL_MAX_SIZE` | 数据库连接池最大连接数，默认 10。 |
| `IOT_BOUND_CACHE_TTL_SECONDS` | 已绑定设备缓存时间，默认 3600 秒。 |
| `IOT_BOUND_NEGATIVE_CACHE_TTL_SECONDS` | 未绑定设备负缓存时间，默认 300 秒。 |

### 10.2 日志目录

上传日志按日期和小时目录组织，示例:

```text
backend\logs\app_upload\YYYYMMDD\HH\upload_YYYYMMDD_HH_001.log
```

### 10.3 运维检查

运维人员应定期检查:

- 上传日志是否持续生成。
- `iot_file_offsets` 中是否存在长时间未完成文件。
- 文件处理延迟和积压是否持续增长。
- 数据库连接数、慢 SQL、锁等待是否异常。
- 最新指标表是否持续更新。

## 11. 压测操作

### 11.1 压测前准备

1. 确认后端服务、数据库和数据处理服务已启动。
2. 确认测试设备 IMEI 已按压测设计准备并绑定。
3. 确认压测目标地址为后端实际地址。
4. 确认监控采集项已开启，包括后端资源、数据库指标、日志增长和处理积压。

### 11.2 压测场景

| 场景 | 事件速率 | 持续时间 |
| --- | ---: | ---: |
| 基准负载 | 15 events/s | 30 分钟 |
| 峰值负载 | 75 events/s | 20 分钟 |
| 极限负载 | 150 events/s | 10 分钟 |

### 11.3 观测指标

压测报告至少应包含:

- HTTP 发送数、成功数、失败数、成功率。
- 接口延迟 P50、P95、P99、最大值。
- 每秒发送量和成功量。
- 后端 CPU、内存、磁盘 IO。
- 数据库连接数、TPS、慢 SQL、锁等待。
- 上传日志增长速度。
- 文件处理最大积压和压测结束后的清空时间。

## 12. APK 打包操作

### 12.1 默认打包

在项目根目录执行:

```powershell
.\build-apk.bat
```

默认输出:

```text
dist\hospital-v5-harmonyos-4.2-debug.apk
```

### 12.2 指定后端地址

可指定电脑局域网 IP 或完整后端 URL:

```powershell
.\build-apk.bat 172.19.51.96
.\build-apk.bat http://172.19.51.96:8000
```

### 12.3 安装验证

安装 APK 后检查:

1. App 名称显示为安小记。
2. 可以正常登录。
3. 健康监测页面能访问后端数据。
4. 真机访问时没有使用 `localhost` 后端地址。

## 13. 常见问题处理

| 问题 | 可能原因 | 处理方式 |
| --- | --- | --- |
| 健康监测无数据 | 当前用户未绑定设备或设备无上报 | 先新增设备并确认 IoT 平台有数据推送。 |
| 手机无法访问后端 | 后端地址使用了 `localhost` 或网络不通 | 使用电脑局域网 IP，确认手机和电脑在同一网络。 |
| 新增设备失败 | IoT 平台未返回设备信息或设备已存在 | 检查 IMEI、平台设备状态和后端日志。 |
| 参数设置失败 | 平台指令创建失败或参数不支持 | 检查设备类型、参数映射和平台返回信息。 |
| 报警记录为空 | 时间范围内无报警或设备未绑定 | 调整时间范围并确认设备绑定关系。 |
| 趋势图无点位 | 指标无历史数据或查询范围过大 | 选择已有数据的日期范围，检查健康事件入库。 |
| 文件处理积压 | 数据库写入慢、处理服务停止或批次过小 | 检查处理服务、数据库性能和批处理配置。 |

## 14. 操作注意事项

1. 生产环境不得将平台密钥、数据库密码写入移动端或公开文档。
2. 执行压测前应确认目标环境，避免误压生产系统。
3. 修改设备参数前应确认设备类型和参数含义。
4. 处理服务异常停止后，应优先检查偏移量表和错误日志。
5. 新增设备类型时，应同步更新设备类型字典、参数映射、页面展示和测试数据。
