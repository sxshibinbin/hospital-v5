# Git Push 输出格式参考

---

## ⚠️ 静默返回模式说明

当 git-push 作为 ai-auto-dev 的子技能被调用时，采用**静默返回模式**：

- **不输出任何报告或总结**
- 只更新索引文件（exec_prog.md 和 sched_log.md）
- 直接返回，让主调度继续执行 Step 7

**检测方式**：检查 `DOCS/{需求号}/sched_log.md` 是否存在

| 模式 | 输出方式 |
|------|----------|
| 静默返回模式 | 只更新索引文件，不输出报告 |
| 独立调用模式 | 输出完整报告 |

## 过程文档模板

写入 `worktree-{需求号}/DOCS/{需求号}/Git提交/exec_prog.md`（追加模式）：

```markdown
## 执行记录 - YYYY-MM-DD HH:MM:SS

### 提交信息
- **Commit**: [hash]
- **消息**: #需求号 #子任务1 #子任务2 ... 提交说明
- **分支**: [分支名]
- **需求号**: [需求号]
- **关联工作项**: [需求号], [子任务1], [子任务2], ...
- **子任务获取**: ✅ 成功获取 N 个子任务 / ⚠️ 获取失败（仅关联需求号）

### 变更文件
| 文件 | 变更 |
|------|------|
| [文件名] | [增删行数] |

### 状态
- **提交状态**: ✅ 成功 / ❌ 失败
- **推送状态**: 待执行 / ✅ 已推送

### 需求状态更新
| 项目 | 内容 |
|------|------|
| 需求号 | [需求号] |
| 更新前状态 | [查询到的状态] |
| 更新后状态 | 已解决 / 未更新 |
| 更新时间 | [时间] |
| 结果 | ✅ 成功 / ⚠️ 跳过 / ❌ 失败 |

**失败原因**（如有）：
- [具体失败原因，如"需求状态为'活动'，需先完成需求分析"]

---
```

## 错误处理

| 场景 | 处理方式 |
|------|----------|
| 准入失败 | 提示"前置步骤未完成，不具备提交代码的条件"，显示未完成步骤列表，退出流程 |
| 网络错误 | 显示错误，自动重试最多3次 |
| 权限错误 | 显示错误，提示检查认证并退出 |
| 推送失败 | 显示错误详情，自动重试最多3次 |
| 保护分支 | 拒绝推送，报错退出 |
| 工作区干净 | 跳过提交步骤，直接进入推送检查 |
| 需求状态非"已分析" | 记录失败原因，提示"当前需求状态为[X]，需先完成需求分析才能更新为'已解决'，请人工处理" |
| TFS 查询失败 | 记录失败原因（网络错误/权限问题），提示人工处理 |
| TFS 更新失败 | 记录失败原因，提示人工处理 |
| 需求不存在 | 提示"需求号[X]不存在于TFS系统，请检查需求号是否正确" |
