## 错误处理

| 场景 | 处理方式 |
|------|----------|
| 准入失败 | 显示未推送提交 + 推送选项 |
| 合并冲突 | 显示冲突文件 + 解决策略选项 |
| 编译失败 | 显示错误 + 终止/继续选项 |
| 测试失败 | 显示失败用例 + 终止/继续选项 |
| 推送失败 | 显示错误 + 重试选项 |
| 保护分支 | 拒绝推送 + 报错退出 |
| 需求号解析失败 | 询问用户提供需求号或跳过 |
| 标签添加失败 | 记录警告 + 提示手动添加 |

## 需求号解析规则

从分支名中提取需求号的常见模式：

| 分支命名模式 | 需求号提取 |
|-------------|-----------|
| `AI/260514` | `260514` |
| `feature/12345` | `12345` |
| `bugfix/67890` | `67890` |
| `需求12345-xxx` | `12345` |
| `REQ-67890` | `67890` |
| `task/1234567` | `1234567` |

**解析逻辑**：
1. 提取分支名中的数字序列（至少5位，TFS工作项ID通常为5-7位）
2. 如有多个匹配，取最后一个数字序列（通常为需求号）
3. 如无法解析，询问用户
