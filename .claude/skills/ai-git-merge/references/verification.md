# Git Merge 验证命令

合并后必须验证代码可编译可运行。

## 项目类型检测

```bash
[ -f "pom.xml" ] && echo "maven"
[ -f "package.json" ] && echo "npm"
[ -f "build.gradle" ] && echo "gradle"
```

---

## 验证命令映射

| 项目类型 | 编译命令 | 测试命令 |
|----------|----------|----------|
| Maven | `mvn compile -q` | `mvn test -q` |
| Gradle | `gradle compileJava` | `gradle test` |
| NPM | `npm run build` | `npm test` |

---

## 验证输出格式

**成功**：
```
🔍 代码验证...

• 项目类型: Maven
• 编译状态: ✅ 成功
• 测试状态: ✅ 成功 (156 cases)
• 耗时: 12.3s
```

**失败**：
```
❌ 验证失败

• 编译状态: ❌ 失败
• 错误信息: [简要错误]

问题：验证失败，是否继续？
选项：• 终止（不推送）• 继续（强制推送）
```

---

## 验证原则

验证是质量保障的关键环节，合并可能：
- 引入编译错误（依赖冲突、语法问题）
- 破坏测试用例（逻辑变更、数据不兼容）

推送前验证确保代码质量，避免污染远程仓库。
