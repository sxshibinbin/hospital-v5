# Stage 1: 前置产出物收集

## 目标
通过 `work_item_id` 定位并读取 PRD解析Agent、架构设计Agent、代码审查Agent 的产出物，汇总测试要点。

## 执行步骤

### 1.0 初始化输出目录

**⚠️ 必须首先执行：创建 DOCS/{work_item_id}/自动化测试/ 目录**

1. 创建输出目录：
   ```
   目标路径: DOCS/{work_item_id}/自动化测试/
   ```
   使用 `Bash` 工具执行（不能用 `&&` 组合）：`mkdir -p DOCS/{work_item_id}/自动化测试/`

2. 初始化 exec_prog.md：
   - 从模板 `@exec_prog.md` 读取内容
   - 替换 `{{work_item_id}}`、`{{task_id}}`、`{{start_time}}` 等占位符
   - 设置 `current_stage = Stage1`，`status = 🔄 Running`
   - 写入路径：`DOCS/{work_item_id}/自动化测试/exec_prog.md`

### 1.1 读取PRD解析结果

1. 构造路径：`DOCS/{work_item_id}/PRD解析/`
2. 查找文件：搜索 `*报告*.md`、`*需求*.md`、`*功能点*.md`
3. 提取内容：
   - 需求功能点清单（Feature List）
   - 验收标准（Acceptance Criteria）
   - 业务流程描述
   - 用户故事（User Story）
4. 记录到测试要点清单

### 1.2 读取架构设计结果

1. 构造路径：`DOCS/{work_item_id}/架构设计/`
2. 查找文件：搜索 `*架构*.md`、`*接口*.json`、`*模块*.md`
3. 提取内容：
   - 模块划分与职责
   - 接口定义（REST API / gRPC / 内部接口）
   - 数据模型与实体关系
   - 依赖关系与外部服务
   - 架构约束（性能、安全、可扩展）
4. 记录接口契约清单

### 1.3 读取代码审查结果

1. 构造路径：`DOCS/{work_item_id}/代码审查/`
2. 查找文件：搜索 `*报告*.md`、`*审查*.md`
3. 提取内容：
   - 问题清单（按严重级别）
   - 风险点（高、中、低）
   - 修复建议
   - 质量评分
   - 技术栈信息
4. 记录审查问题清单

### 1.4 汇总测试要点

合并以上三路输入，生成统一的测试要点清单：

| 来源 | 要点类型 | 详细内容 | 优先级 |
|------|---------|----------|--------|
| PRD | 功能测试点 | 需求功能点 + 验收标准 | P0-P2 |
| 架构 | 接口测试点 | API定义 + 数据约束 | P0-P1 |
| 架构 | 边界测试点 | 数值范围 + 长度限制 | P1-P2 |
| 审查 | 异常测试点 | 已发现问题 + 风险点 | P0-P3 |

## 产出物
- `DOCS/{work_item_id}/自动化测试/test_points_{work_item_id}.json` — 汇总的测试要点清单
- 包含每个要点的来源标签（prd/arch/review）和优先级
- `DOCS/{work_item_id}/自动化测试/exec_prog.md` — 执行进度文档（初始化）

## 检查点
- [ ] PRD解析结果已读取（功能点数 > 0）
- [ ] 架构设计结果已读取（接口数 > 0）
- [ ] 代码审查结果已读取（问题数 ≥ 0）

- `prd_*`, `arch_*`, `review_*` — 前置Agent状态
- `s1_1_*` ~ `s1_4_*` — 各步骤状态
