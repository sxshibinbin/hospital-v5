# Stage 2: 测试用例设计

## 目标
基于 Stage 1 汇总的测试要点，按优先级生成全场景测试用例。

## 核心策略：用例关联性

**每条测试用例必须标注其来源**，确保可追溯：

```
用例编号格式: TC-{来源缩写}-{序号}
  来源缩写: PRD/ARCH/REVIEW/MED
  示例: TC-PRD-001, TC-ARCH-005, TC-REVIEW-003, TC-MED-002
```

### 来源映射规则
| 来源缩写 | 对应前置Agent | 用例类型 |
|---------|--------------|---------|
| PRD | PRD解析Agent | 正常场景、验收标准验证 |
| ARCH | 架构设计Agent | 接口测试、边界值 |
| REVIEW | 代码审查Agent | 异常场景、回归验证 |
| MED | 内置医疗规则库 | 医疗合规测试 |

## 执行步骤

### 2.1 正常场景用例（来源：PRD）

- 对于每个需求功能点，生成 1~3 条 Happy Path 用例
- 参考验收标准，确保覆盖所有成功场景
- 重点关注医疗业务流程连续性

### 2.2 接口测试用例（来源：ARCH）

- 对于架构设计中的每个接口定义：
  - 正常请求验证（正确参数 → 期望响应）
  - 参数格式验证（JSON Schema 校验）
  - HTTP 状态码验证（200/201/204/400/401/403/404/500）
  - 接口幂等性验证
- 参考 `references/java-test-templates.md` 中的接口测试模板

### 2.3 异常场景用例（来源：REVIEW）

- 对于代码审查发现的每个问题类型：
  - 如果问题已被修复 → 验证修复是否有效
  - 如果问题未修复 → 验证异常处理是否到位
- 针对审查中标记的风险点，设计专项异常用例
- 重点覆盖：空指针、SQL注入、XSS、事务回滚

### 2.4 边界值用例（来源：ARCH + PRD）

- 基于架构设计中的参数约束：
  - 数值参数：最小值、最大值、边界值 ±1
  - 字符串参数：空串、最大长度、超长
  - 枚举参数：所有合法值 + 非法值
- 基于需求中的业务规则：
  - 处方剂量最小/最大
  - 患者年龄边界（成人/儿童切换）
  - 分页参数边界

### 2.5 医疗合规用例（来源：内置医疗规则库）

参考 `references/medical-test-cases.md`，针对当前产品线生成专项用例：
- 患者数据隔离（不同医生查看不同患者）
- 处方合法性校验（药物相互作用）
- 护理记录完整性
- 审计日志检查
- 数据脱敏验证
