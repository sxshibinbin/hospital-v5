# Bypass 策略表

ai-auto-dev 全自动执行时，所有子Agent必须跳过用户交互点。

## 全局规则

- **禁止调用 AskUserQuestion**
- 子Agent自行读取 DOCS 目录获取上下文
- 所有状态和产出物写入 exec_prog.md

---

## 子Agent Bypass 策略

### backend-coder

| 正常交互点 | Bypass策略 |
|------------|------------|
| 用户确认任务列表 | 自动确认，直接执行 |
| 选择技术栈 | 自动识别（检测 pom.xml、build.gradle、go.mod、requirements.txt） |
| 确认编码完成 | 自动继续，不等待用户确认 |

### frontend-coder

| 正常交互点 | Bypass策略 |
|------------|------------|
| 用户确认任务列表 | 自动确认，直接执行 |
| 选择框架/组件 | 自动识别（检测 package.json） |
| 确认编码完成 | 自动继续，不等待用户确认 |

### code-reviewer

| 正常交互点 | Bypass策略 |
|------------|------------|
| 用户确认评审结果 | 自动记录问题，不等待确认 |
| 是否修复问题 | 发现问题自动记录到 exec_prog.md，后续重试处理 |

### auto-tester

| 正常交互点 | Bypass策略 |
|------------|------------|
| 用户确认测试范围 | 全量测试，不询问范围 |
| 测试失败是否继续 | 自动记录失败信息，继续流程 |

### git-committer

| 正常交互点 | Bypass策略 |
|------------|------------|
| 用户确认提交内容 | 自动提交所有变更 |
| 选择提交分支 | 使用 feature/{需求号} 分支 |
| 是否合并到目标分支 | **不自动合并**（保证基础分支稳定性） |

---

## 异常流程 Bypass

| 异常场景 | Bypass处理 |
|----------|------------|
| 步骤失败 | 自动重试（最多MAX_RETRY_COUNT次） |
| 超过重试上限 | 自动记录失败，继续处理下一个需求号 |
| 步骤超时 | 自动判定超时，触发重试机制 |
| 子Agent返回错误 | 自动读取 exec_prog.md 获取断点，重新执行 |
| 清理前验证失败 | 记录原因，保留worktree，跳过清理 |

---

## exec_prog.md 状态写入规则

子Agent完成后必须更新 exec_prog.md：

### 成功
```markdown
## 执行状态
- 状态: success
- 结束时间: {当前时间}
## 产出物
- 文件列表: [产出的文件]
```

### 失败
```markdown
## 执行状态
- 状态: failed
- 当前断点: {失败位置描述}
## 错误信息
- 错误类型: {错误类型}
- 错误详情: {具体错误}
```
